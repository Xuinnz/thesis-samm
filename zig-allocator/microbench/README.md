# microbench — SAMM with and without the Node-API bridge

Replays the characterization's own request stream (real per-request allocation
sequences from `training_trace.csv`, opened and closed at the real request
boundaries from `scope_trace.csv`) through every layer between a route and
physical memory. The replay is compressed in time; sizes, ordering, overlap
between requests, and lifetimes are unchanged.

| Layer | What runs | Source |
|---|---|---|
| `engine` | SAMM engine alone, no bridge | `engine_bench.zig` (imports `../src` read-only) |
| `bridge` | one `samm.allocate()` round trip that does no memory work | `js_bench.js` |
| `samm` | the server's `allocateBuffer()` → SAMM through N-API | `js_bench.js` |
| `v8` | the server's `allocateBuffer()` → `Buffer.allocUnsafe()` | `js_bench.js` |
| `malloc` | C allocator only, no V8 (glibc or jemalloc) | `engine_bench.zig` |

Nothing under `../src`, `../build.zig` or the addon is built or modified. The
Node layers load the addon already inside the production image
(`samm-enabled:bench`), and `run.sh` refuses to run if that image predates the
current routing table.

```bash
RESULTS=results-<date> ./run.sh          # full run: 7 layers x 7 traces x {no touch, touch}, 5 trials + 1 warmup
TRIALS=3 RESULTS=... ./run.sh            # quicker
TRACES=aggregate TOUCH_MODES=1 TRIALS=30 RESULTS=... ./run.sh   # one noisy cell, more trials
node report.js results                   # re-print the tables from saved results
```

`./gated_run.sh [results-dir]` does the same full run, plus the 30-trial
aggregate touch cell, but only after a host-health probe passes (k6 startup
<= 80 s, V8 microbench within 0.90-1.10x of `results/`, GC time per collection
<= 1.10x). It checks k6 startup again afterwards and checksums `results/`.

`run.sh` refuses to write into a directory that already holds results, so a
finished run is never overwritten: every run needs its own `RESULTS`. `results/`
is the 2026-09-19 run.

`report.js` prints medians (as before), then mean ± sample SD with the trial
count for every cell, and the full spread (min–max, CV, 95% CI of the mean) for
any cell with 10 or more trials.

Traces (`.out/traces`, regenerated by `extract_trace.js`): `mix` (all
call-sites as served) and one per call-site. The extractor walks each trace
exactly as the replay will and fails if any allocation would leak.

Results: `results/*.jsonl` (one line per trial) and `results/summary.txt`.

Caveats:
- One pinned core. No network, no JSON, no Express. This isolates the
  allocation path and is not a request-latency measurement.
- Traces with one allocation per request (cache, ingest, fetch, process,
  aggregate) report a per-request cost: region open and close, plus about
  25–60 ns of timer overhead.
- Single-call-site results in touch mode are noisy (up to 109% trial spread).
- `aggregate` is routed to **System**, so SAMM never serves it. Its SAMM rows
  measure SAMM declining and the fallback doing the work: the engine row is the
  routing lookup plus `malloc`, the N-API row is the bridge round trip plus
  `Buffer.allocUnsafe()` — the same allocation as the V8 rows. The report marks
  the column `aggregate*`; the gap to the baseline there is the cost of
  declining plus noise, not a SAMM result.
